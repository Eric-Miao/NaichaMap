# NaichaMap 线上可靠性与 UI 精修设计

## 意图

让已上线的 NaichaMap 首先可靠完成“查到附近饮品店”，再让界面从通用卡片模板提升为精确、统一、适合上海移动场景的地图工具。美化的优先级是结构、对齐、尺寸和状态一致性，颜色只负责分类和反馈。

## 目标

- 修复线上 `/api/nearby` 首次查询返回 `PROVIDER_UNAVAILABLE`，同时保留 30 天缓存、保守商场判断和隐私边界。
- 保留“地图 + 上滑菜单”的现有交互与全部产品功能。
- 在定位首屏、地点搜索、地图、门店抽屉、状态页和纠错弹窗中统一内容基线、间距、控件高度、圆角、图标和状态表现。
- 手机优先，并保证中等宽度与桌面容器对齐；支持键盘、触摸、安全区和减少动态效果。

## 非目标

- 不增加楼层、导航、小程序、账号、收藏或新数据源。
- 不做卡通插画主题，不为了“更丰富”增加无功能装饰。
- 不更改高德、Supabase 或 Vercel 的密钥模型，不记录经纬度、原始 IP 或请求体。

## 已确认的视觉方向

采用克制的“上海城市导览贴纸感”：操作模式仍是成熟地图工具；辨识度来自门店类别标记、地点标签和精确的排版节奏，而不是大面积换色。

### 选择过的方案

1. **城市导览贴纸感（采用）**：地图主导，少量类别色和地点标签承载个性；能兼顾效率与辨识度。
2. **极简地图工具风（未采用）**：最清晰，但品牌记忆不足。
3. **奶茶杯封插画风（未采用）**：记忆点强，但会挤压地图信息并偏卡通。

## 视觉系统

- **内容基线**：移动端统一 16px 左右内容轨道；紧密间距 8px，常规 12/16px，分组 24px。
- **控件**：主按钮、次按钮和输入框统一 48px；图标占 20px 固定槽位，按钮文案以整个控件为基准真正居中；触摸目标不低于 44px。
- **圆角**：表面 18px、控件 12px、类别标签仅使用胶囊圆角；同角色不出现多个近似值。
- **字体**：以苹方/系统中文无衬线为主；标题紧凑但不挤压，正文 1.55–1.65 行高，距离与数量使用等宽数字特性。
- **颜色**：雾白底、墨色文字、低对比边线；茶饮、咖啡、果饮只在标记、首字砖和选中状态使用稳定的语义色。
- **动效**：保留一次抽屉位移、标记选中和复制提示；全部使用 transform/opacity，并尊重 `prefers-reduced-motion`。
- **签名元素**：地图上的商场标签像城市导览贴纸，类别与抽屉列表使用同一色语义；不添加独立插画。

## 附近查询可靠性

- 单个饮品分类请求失败时，不应让其他成功分类全部丢失；至少一个饮品分类成功即可继续去重、分类和保存。
- 商场查询失败时，仍返回饮品门店并安全降级为“附近”，不能阻塞核心结果。
- 所有饮品分类均失败时才返回可重试的提供方错误。
- 线上诊断只能记录稳定错误代码和阶段，不记录坐标、请求体、原始 IP、密钥或上游完整响应。
- 冷查询成功后，第二次同网格查询应命中 Supabase 缓存并减少高德调用。

## 验收

- 上海国金中心公开坐标的线上查询返回至少一个门店组，不再返回 `PROVIDER_UNAVAILABLE`；再次查询返回 fresh/refreshed 数据。
- 定位首屏两个按钮等高，图标存在时文字中心仍与卡片中心对齐。
- 搜索输入和搜索按钮等高；结果列表、状态卡和纠错弹窗共享相同内容轨道。
- 地图顶栏、抽屉标题、分类标签和门店列表的左右边缘一致。
- 360px、412px、768px 和宽桌面无水平溢出；长店名截断且不挤压复制按钮。
- 完整测试、类型检查、lint、生产构建、移动端端到端测试和 Impeccable 单次机械检查通过。
